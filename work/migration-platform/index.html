01 / The problem

Finding a pathway shouldn't start with guesswork

For students and temporary visa holders, working out whether they might qualify for permanent residency means piecing together points tests, occupation lists and each state's own nomination criteria — often before they can afford an agent.

Pathwise turns an applicant's profile into a clear picture of which pathways they may match and why. It gives general information only — not migration advice — and points people to a registered migration agent before they apply.

03 / For applicants

From profile to pathway

Pathway matching

Each pathway is checked criterion by criterion — “7 of 9 criteria appear satisfied” — with a points total and an overall “potential match” or “partial match” result.

Compare states

The same profile is evaluated against each state or territory's own published nomination criteria, sorted by closest match.

What-if scenarios

Try changes such as a better English score and see the effect. Scenarios store only the differences from the real profile.

Ask with sources

An AI assistant answers pathway questions with references to the government sources behind each answer.

Every profile field is optional and is only collected when a rule or points calculation actually uses it. Results are saved over time so applicants can see how their position changes.

05 / Admin & rules

Rules you can trust, changes you can trace

  • Admins manage the eligibility rules, occupation data and government sources that every result is built from.
  • Changes follow a four-eyes workflow: one admin drafts, a second admin verifies, then it's published.
  • Every admin change — around 53 kinds — is written to an audit log with the values before and after, plus the admin's device and session.
  • Admins can see account details but cannot open the contents of an applicant's profile.
  • Terms of Use, Privacy Policy and Agent Terms are versioned; when a new version is published, users must accept it before they can carry on.
06 / Security & privacy

Treated like financial or health data

Accounts

Passwords hashed with argon2; session tokens stored hashed and rotated on every use; rate limits on sign-in, registration and resets.

Access checks

Every profile read and write is checked on the server. Asking for someone else's record returns “not found”, so it doesn't even confirm it exists.

Admin protection

Admin sign-in needs an authenticator app plus single-use recovery codes, with admin accounts kept in their own table.

Clean logs

An automatic filter stops passwords, tokens, reset links, two-factor secrets and profile contents ever reaching the logs.

Card details are entered on Stripe's own page, Google sign-in asks only for an email address, and the AI assistant is never sent raw profile fields. Applicants can export their own data. Before any real users join, I wrote a data-retention and privacy brief for a privacy lawyer, so retention and deletion rules are set by legal advice rather than guesswork.

07 / Where it's at

Built, tested, and heading for legal review

  • The applicant, agent and admin areas are built and running with test data.
  • Next: privacy-lawyer review of retention and the legal documents, choosing hosting, then a small group of real testers.

The platform hasn't launched. Details are kept high-level, and no real user data is shown.
